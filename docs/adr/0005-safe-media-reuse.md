# ADR 0005: Safe Media Reuse

**Date:** 2026-08-17
**Status:** Accepted

## Context

NetEase、文件标签和 Plex 刮削器可能展示不同的标题、艺人、专辑与 MusicBrainz 信息。继续比较这些元数据会增加误绑定风险，也让故障取决于多个外部匹配器，难以解释和排查。

## Decision

运行时只接受两种媒体关联：

1. YunPlex 管理的本地媒体被 Plex 以唯一、完全一致的 `Media.Part.file` 路径索引，建立 `path` 关联。
2. 用户在同步源的歌曲上下文选择一个具体 Plex 媒体，建立 `manual` 接管关联。

标题、艺人、专辑、时长、provider GUID 与 MusicBrainz 不再参与自动身份判断。无法验证现有关联时，系统下载带网易云歌曲 ID 的独立托管副本。同一精确路径出现多个 Plex 身份时停止自动处理，不任选一个。

2026-08-26 补充：无法验证身份时由全局“未验证媒体”策略决定下载独立托管副本，或进入“等待手动选择”。等待状态不是同步失败；用户仍可在同步源歌曲上下文选择 Plex 现有媒体，或单独触发“下载并托管”。这一补充不改变上述两种强身份及精确路径要求。

2026-08-30 补充：歌单首次同步增加用户确认的批量 Explicit Adoption（“首次媒体接管”）。它是一次性硬门：分析阶段只读取网易云歌单和 Plex 音乐库，候选结果保存后进入 `awaiting_action`，确认前不得创建下载任务、写入身份或修改 Plex。候选分层可以使用精确 `[netease-{songId}]` 路径标识，以及严格的本地标题、版本、完整艺人集合、专辑、曲号和时长证据帮助用户批量审核；只有用户提交的“使用 Plex 媒体”才形成全局 `manual` 关联。这些候选规则不进入日常 `lookup.ts`，因此不增加第三种常驻自动身份。

首次媒体接管的“下载并托管”和“暂缓”仅作为初始化快照的稀疏处理决定。提交后仍由唯一 Source Convergence 链路负责下载、扫描和 Plex 写入；未来新增歌曲继续遵循正常未验证媒体策略。专辑来源不参与该硬门。

候选审核、身份事件和 MusicBrainz 缓存退出当前 schema。历史迁移仍可短暂创建旧表以兼容升级，但当前迁移结束时会删除它们，并清除非 `path`/`manual` 关联。

## Consequences

- Plex 刮削器可以改变展示元数据，不影响托管媒体复用。
- 外部媒体不会被静默接管；首次接管需要一次明确选择。
- 大型现有歌单可以先完成零副作用分析，再按证据等级分页审核；初始化扫描全局串行并支持中断恢复。
- 未确认歌曲可能增加下载与存储，但不会因相似元数据误复用。
- 托管下载保留触发它的 Playlist Source 上下文；文件成功且标签完成后只提交一次 Local Media Asset。
- 文件名默认包含 `[netease-{songId}]`，减少重名覆盖并提供可见来源标识。
- 删除保护仍按具体 `playlistItemID`、完整目标、身份版本和写后读回执行。

ADR 0004 被本决策取代；ADR 0003 的媒体归属与文件连续性原则继续有效。
