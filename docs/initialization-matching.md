# 初始化匹配与快速接管

歌单第一次同步前会先准备歌曲安排：优先复用 Plex 音乐，缺少的尝试下载。审批流程按推荐规则准备草案；“直接开始！”采用当前排序的第一个候选，没有候选的再下载。匹配不合适时可在“歌曲与媒体”调整。

来源也可以跳过接管。跳过会按普通同步的未接管策略处理，可能马上排很多下载。

## 添加与开始同步

1. 推荐在新建收藏时点右侧主按钮“审批初始化”，进入首次准备页。分析完成后，歌曲已有默认安排，列表默认展开；可逐首改选候选、下载或暂缓，再点“开始下载并同步”。匹配规则与证据按需展开。尚未提交时离开会提醒，草案保留。
2. 希望交给系统处理时点左侧次按钮“直接开始！”。后台依次分析、安排、下载并更新 Plex，离开页面后继续处理；歌曲安排同样默认展开。一次添加多张歌单时均会排队，可在页面上切换查看。
3. 页面持续显示实际处理阶段。只有后续同步完成且目标歌曲都已处理，才显示“Plex 已同步 N / N 首”；暂缓、版权受限或失败会列出未同步数量与处理结果入口。安排应用成功不代表音乐已经入库。

新建收藏默认启用后续定时同步，可在收藏设置中关闭；关闭后也能执行本次同步。提交安排、直接开始和分数线方案共用持久队列。排队后暂时锁定编辑；取消会保留选择，重新提交时复核身份版本、归属与路径。已开始执行或已结束的方案会释放撤销数据，歌曲安排与评分证据仍保留。重复请求不会重复应用同一方案。

## 默认安排与自定义

推荐分类与评分共用元数据事实。多个候选的质量优选、目标专辑唯一优选控制推荐分类；主动选择自动安排或分数线方案时，按最高分的可用候选处理，仍遵守版本、路径和必需字段的排除条件。

审批初始化的默认草案会保留已确认文件，按推荐规则安排其余歌曲。“直接开始！”则采用当前排序的第一个有文件路径的候选，找不到候选才安排下载；艺人、版本和媒体归属差异保留为提示，多首歌曲可以共用文件，各自保留歌单位置。

普通自动安排保留人工修改。提交暂缓歌曲时选择“采用首个候选并开始”，会重新安排这些歌曲：有候选就采用第一项，不再按艺人中英文、版本差异或共享媒体规则改为下载；没有可用文件路径才安排下载。整类或选中项操作会覆盖该范围内的草案选择，均不创建撤销副本。

“推荐匹配”“需要核对”和“存在冲突”是候选分类，不限制用户明确采用候选。列表支持对选中歌曲或跨页全选结果执行“采用第一个候选”；没有候选的选中歌曲保持原安排。“需要核对”和“存在冲突”也可以整类采用第一项，没有候选的安排下载。

草案仍有暂缓歌曲时，提交前会列出数量与原因，并允许采用首个候选、返回调整，或明确只同步其余歌曲。主动暂缓的歌曲不会下载或加入 Plex。

“按分数线重新安排”保留精细控制：分数线为 0–100，达标的采用，其他安排下载。这个操作会重写未提交的手动选择，界面会先提示；已确认文件保留。可以只保存或直接开始，只保存且未再次编辑时，可恢复保存前的安排。自动安排不创建撤销副本，可以逐首调整。

## 评分与风险

评分满分 100，只比较元数据：标题 35 分、艺人集合 35 分、时长 20 分、专辑 7 分、曲序 3 分。有争议的版本差异每处扣 10 分，最多扣 30 分；缺失项不加分。文件名、音质和目录偏好不加分。

推荐规则和分数线方案会排除演唱者冲突、歌曲 ID 矛盾、版本冲突、媒体路径缺失或不唯一的候选。专辑或曲序按设置要求匹配时，缺失也会阻止推荐。明确选择“采用第一个候选”或“直接开始！”时，艺人、版本和归属差异仅作提示；执行仍核对所选文件是否存在、路径和绑定版本是否变化。

分数表示匹配程度，不是正确率，85 分也不保证匹配成功。分数线越低，误匹配风险越大，需要人工抽查；第一名和第二名接近时只提示风险。

## 设置分组

- “匹配总开关与预设”：增强匹配默认关闭；预设只填可见参数，之后改动即为自定义，切换预设不影响已设的别名和候选优先目录。
- “标题与艺人规则”：简繁、全半角、双语、模糊标题、扩展召回等如何比较标题和艺人；路径只做提示，不能单独建立关联。
- “批量推荐策略”：多个候选时默认选质量最高的合格候选，也可改为全部复核；忽略缺失合作歌手、拉丁重音、双语交叉、MusicBrainz 等增强项默认关闭，开启也不放宽版本和身份保护。
- “快速初始化”：只保存快速方案的默认分数线，不影响已有方案。
- “时长与版本规则”：区分直接推荐和人工确认；现场、伴奏、翻唱、混音等版本差异不会被时长或艺人证据掩盖。

## 艺人名与 MusicBrainz

“艺人名称”里的别名组让不同写法被当成同一艺人；“原名称 → 写入名称”是单独的写入替换，不会重命名已有文件。别名建议来自本次分析，需要你确认保存才生效。

两个编辑页都支持 JSON 批量编辑。匹配别名使用规则数组，每条包含 `name`（艺人名称）、`aliases`（别名数组）和 `enabled`（是否启用）；写入替换使用“原名称 → 写入名称”的 JSON 对象。应用只修改当前类型的规则，另一类保持不变；格式有误时保留输入。先应用到草稿，再使用页底保存条保存，取消批量编辑会保留原有规则。

MusicBrainz 是可选的外部补充，用来找艺人异名，默认关闭且要配合艺人别名使用。只发送待审艺人名，只采纳名称精确、没有同名歧义的记录，也不会自动修改手工别名。

## 重新分析、共享确认与纠错

匹配规则有变化时，原结果只能查看，重新分析才能继续。Plex 音乐库在分析后有变化时，只提示可以重新分析，当前选择和编辑权限保留。重新分析会重新读取数据、生成新方案，已确认的媒体关联会保留，草案中未提交的选择需要重新确认。

收藏里的“重新分析匹配”只重评系统自动选择、未经人工确认的关联。提交后选择“下载”的歌曲会进入托管副本纠错流程，验证新文件和 Plex 精确路径后才切换，失败保留原文件与原关联；选择“暂缓”则优先于旧关联停止本来源的处理，已有 Plex 条目仍受删除保护。已批准的新下载决定独立于之前的失败记录；本次再次失败达到暂停条件后，不会继续强制每轮完整核对。

自定义模式中，多首歌推荐到同一个 Plex 媒体时可查看整组信息并确认共用。共享只是复用同一个文件，不合并歌曲 ID 和歌单位置，撤销其中一首不影响其他。按推荐规则生成的默认草案会优先尝试独立下载；明确选择“采用第一个候选”时允许共用，后续同步继续保留这些已确认关联。

“歌曲与媒体”里可以做两种纠错：

- 更换匹配：改选其他 Plex 媒体，校验当前关联后保存；启用的收藏会自动对齐。
- 改为下载：另下一份托管副本，经 Plex 验证后才切换；失败保留原文件和原关联。
