# 初始化匹配

## 范围

「设置 → 初始化匹配」配置首次媒体接管的候选规划。增强匹配默认关闭；关闭时保留标准候选规则。它不改变日常 Source Convergence、下载策略或正式身份的建立条件。预设只填入可见参数，继续编辑即为自定义；切换预设保留独立别名字典和首选目录。

保存配置不重新分析既有草案。所有推荐都需要在来源详情确认提交，才能形成 manual 关联。修改规则、试算、导入匹配别名都不会下载、绑定身份或修改 Plex。

## 规则与分级

引擎先保留当前可验证的关联，再处理唯一的网易云文件 ID，最后进行元数据候选召回和核验。增强规则将简繁体、全半角、标点、明确的电影出处、双语标题、曲目艺人和已确认别名用于候选搜索。模糊检索支持较长标题的包含关系及最多 4 个字符、且不超过较短标题长度 25% 的编辑差异，同时要求独立艺人线索和接近时长，只能产生待审候选。

- 标点型标题保留独立原文键，例如 `.` 不会因去标点而变成空标题，也不与 `...` 合并。
- `with`、`Vocal:` 等明确参与者附注提取为艺人证据，`Vocal Mix` 保留为版本信息。
- 「扩展标题召回」支持括号附注、反向/斜杠双语、数字写法、唱片曲号前缀和古典作品编号与乐章，要求独立艺人或目录线索与有效的接近时长；只进入待审候选。古典作品编号不能独立确定演奏者或录音版本。
- 「专辑曲序补充检索」在标题未找到可信候选时，要求同专辑、同曲序、独立艺人或目录线索，以及不超过推荐毫秒阈值的有效时长，找回译名或错字候选；不同标题不能直接推荐。均衡/发现预设默认启用这两项，保守预设关闭；升级配置按共享默认值补齐。
- 完整艺人名称先比较；多人字段按目标艺人和已确认别名保留完整名称，再解析合作署名。`Florence + The Machine`、`R!N/Gemie`、`Moments With You` 等名称不会因嵌在多人字段中而拆散；支持明确的 `w.`、`as` 署名，不丢弃未知的额外参与者。
- 合辑优先使用 `originalTitle` 的曲目艺人。关闭该选项时使用 Plex 专辑艺人。
- 标准推荐要求完整艺人集合一致；歌曲标题两侧的明确参与者附注也纳入集合。允许主要艺人策略本身只扩大待审候选。
- 「交叉证据推荐」是独立、可关闭的增强选项：必须标题一致、同专辑、正数曲序一致、单一媒体路径、文件名保留同一标题与版本、时差同时满足推荐阈值与比例且不超过 500 毫秒，无版本待审或身份冲突，并且只有一个合格候选。关闭路径提示或将专辑、曲序策略设为忽略时不使用此通道。
- 交叉证据仅覆盖两类：单个中日韩艺人的 Plex 标签是拉丁字母写法，且文件的艺人目录精确对应原艺人；或者至多三位目标参与者中只缺一位，所有已标注参与者都属于目标集合，且专辑主艺人与目标主艺人一致。同文字体系的异名、额外或冲突参与者、多人缺失仍需复核。专辑目录不作为艺人证据，不会自动建立通用别名字典。
- 均衡与发现预设开启交叉证据推荐，保守预设关闭。推荐仅辅助用户批量确认，不验证音频内容，也不自动创建媒体身份。
- 专辑和曲序分别支持必须一致、排序时优先、忽略。可选的「目标专辑唯一优选」只在专辑策略为优先、曲序未忽略时生效：唯一一个候选完整艺人、标题、目标专辑、正数曲序一致，时差不超过 500 毫秒且满足推荐阈值，所有其他可选候选均来自不同专辑时，可推荐该项。保留所有替代候选和优选原因；同专辑重复、仅目录艺人交叉证据、版本与身份冲突不能通过这条规则解除。均衡与发现预设开启，保守关闭。目录和音质排序不解除歧义。
- 推荐默认要求时差同时不超过 2000 毫秒和目标时长的 2%；待审时差默认不超过 5000 毫秒。时长缺失可排除或待审，不能批量推荐。
- 路径与文件名不是外部媒体的身份依据。目录相同本身不足以升级推荐；交叉证据通道还必须满足上述全部条件。
- 推荐还要求唯一合格候选（或目标专辑唯一优选确认唯一严格吻合项）和单一媒体路径。重复副本偏好仅改变显示顺序，不自动绑定或删除文件。

版本检查保留具体混音作者、发行说明和年份，识别括号与破折号后缀。现场、伴奏（含日文卡拉 OK）、独唱/合唱/朗诵、翻唱、混音作者、语言、变速等冲突不能被时长或艺人证据抵消。Remaster 可选择严格、待审或允许；单曲/专辑/Radio Edit 与 Explicit/Clean 可选择严格或待审。版本信息只存在于一侧时可排除或展示待审；“严格”候选受“显示版本冲突”选项控制是否展示，但不能批量推荐。

文件中属于另一首歌的网易云 ID、其他歌曲的现有关联，以及同一分析中多首歌曲争用一个媒体，都会形成身份冲突。提交仍重新检查路径和关联版本，分析结果不代替提交时的检查。

结果沿用现有持久化等级：`preserved`、`strong_id`、`high_confidence`、`possible`、`ambiguous`、`unmatched`、`metadata_missing`、`conflict`。疑似重复副本和版本冲突记录于证据分类，在试算中单独计数。`high_confidence` 表示满足当前推荐规则，并不表示音频内容已经验证。

版本识别也覆盖标题末尾成对的波浪线和连字符标注，例如 `〜Instrumental〜`、`-Instrumental-` 和 `～album version～`。这些标注与括号版本执行相同保护；扩大标题召回不能绕过伴奏、现场等版本冲突。

## 独立别名字典

### 批量推荐策略

以下独立选项仅在增强初始化匹配中生效，当前规则版本为 8：

- `duplicatePolicy`：默认 `highest_quality`，在满足推荐条件的候选中依次按无损、位深、采样率、码率选择；质量相同或未知时按稳定 ratingKey 顺序选择。该策略优先于目标专辑唯一优选，其他候选保留。设为 `review` 恢复竞争候选复核（目标专辑唯一优选仍可单独开启）。格式与质量只表达用户偏好，不证明录音内容等价。
- `ignoreMissingCollaborators`：默认关闭。开启时仅接受候选的参与者是目标名单的子集且包含目标主艺人；不能忽略陌生艺人或主艺人缺失。仍要求标题、时长、版本、单文件路径等满足推荐条件，不能绕过媒体所有权或跨歌曲争用保护。
- `musicBrainzAliases`：默认关闭，且需要 `useArtistAliases`。只向 MusicBrainz 发送待审艺人名，优先查询高频且艺人尚未对齐的条目。`musicBrainzMinScore` 默认 100（90–100）；搜索分不是正确率，仍要求搜索返回唯一的精确名称/别名记录，截断结果和同名歧义不采纳。合作署名、纯符号和搜索提示不会作为单人别名。
- `foldArtistDiacritics`：默认关闭，仅折叠拉丁艺名上的组合重音（例如 `GIVĒON/Giveon`、`JAŸ-Z/JAY-Z`）。标题、专辑及日文浊音等保持原有比较方式。艺人别名碰撞校验与候选比较使用相同规则。
- `corroboratedBilingualTitles`：默认关闭，需同时开启 `bilingualTitles`。中文标题与中英并列标题相交时，只有完整艺人、专辑、曲序一致且时差不超过 500 毫秒，才允许推荐；不放宽版本、路径或身份保护。

项目名与歌手用冒号连接时，只有各段均在目标艺人或已确认别名集合中，才拆成参与者；完整已知艺名（如 `AC:DC`）优先保留。`瑞葵(mizuki)` 这类双语艺名可在 MusicBrainz 中补查原文，但只有原文和括号名同时出现在同一唯一艺人记录中才采纳，不能仅凭括号自动认定别名。

MusicBrainz 查询顺序优先考虑已有标题、紧密时长支持而艺人未对齐的候选，再考虑其他高频待审艺人，以减少对弱同名候选和疑似缺曲的无效查询。

`musicBrainzMaxArtists` 默认 40（1–200）。请求在进程内串行、间隔至少 1.1 秒，单次超时 8 秒；结果缓存 24 小时、最多 512 条，重启清空。429/503 会遵循短时退避重试一次；仍失败则停止本轮外部请求，保留已获得证据并显示警告，剩余条目沿用普通规则；取消正式分析会中断请求和排队等待。

MusicBrainz 记录（MBID、名称、别名、搜索分和查询警告）与正式草案一起保存，不写入手工别名配置。手工停用和冲突规则优先，不跨不同 MBID 自动合并重叠别名。预览冻结基线的 MB 证据；参数变化后的查询独立记录并复用进程缓存。高质量优选或别名补充可能暴露多首网易云歌曲争用同一媒体，此时结果转为身份冲突，不按已解决计数。

接口依据：[MusicBrainz 搜索接口](https://musicbrainz.org/doc/MusicBrainz_API/Search)、[调用限速与 User-Agent 要求](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting)。

`initializationMatching.artistAliases` 和 `titleAliases` 保存 `{ name, aliases, enabled }` 组。等价名称双向比较；组可停用、编辑或删除。启用组在当前文字归一化规则下不能重叠。

设置中的「艺人名称」统一管理匹配名称和明确的写入替换，下载与文件、初始化匹配提供跳转入口。新建组默认只用于增强匹配；写入替换必须单独添加「原名称 → 写入名称」。修改匹配名称不会自动扩展或改变写入方向。支持批量 JSON 编辑写入映射；未应用或无效的草稿会阻止保存，切换设置分类保留草稿。

持久化和运行契约保持兼容：`initializationMatching.artistAliases` 保存匹配组，`other.artistAliases` 保存有方向的替换，`other.applyAliasToAlbum` 控制专辑艺人替换。旧替换只有两个端点明确属于同一唯一匹配组时才在界面中归组，否则保留为未开启匹配的独立组；不根据替换关系推断艺人等价。保留旧映射的顺序、方向以及匹配组的停用状态。增强分析读取网易云原始艺人名；标准候选算法原有的替换映射兼容路径保持不变。保存规则不会自动重命名既有文件，也不会修改 Plex。

别名建议来自本次快照中标题、专辑、接近的时长和目录艺人的交叉线索。建议可能是刮削错误；只有用户明确加入并保存后才参与后续正式分析。标题别名也不能绕过版本和身份冲突检查。

## 同快照试算

`POST /api/initialization-matching/preview` 接受 `sourceId`、`config` 和可选 `snapshotId`。首次读取网易云、Plex 及关联事实，同时冻结当时的保存参数作为基线。后续传入相同快照 ID，仅重新运行纯候选算法，不再拉取远端。

试算使用来源歌曲数量上限；总目标数与 Plex 全库数量分别显示。前后统计覆盖已有绑定、强身份、推荐、待审、疑似重复、版本冲突、身份冲突、无候选和缺失元数据。逐首列表展示新增、降级、候选变化及理由。关闭一项规则再预览，可以对比它的作用；重叠规则的增益不能直接相加。

快照在单进程内最多缓存 3 份，20 分钟后过期。服务重启也会失效；页面提供刷新入口。切换来源清除旧结果；修改参数后旧结果标为过时；服务失败不会伪装成零候选。预览不持久化接管草案、任务、身份、配置或下载记录。

## 草案与重新分析

正式分析在 `source_initializations` 保存算法版本、完整匹配参数（标准模式包含旧别名）、参数指纹、数据指纹和分析时间。全局配置变化不改写既有草案，也不使参数快照失效。算法版本不兼容时仍要求重新分析。

重新分析前，用同一份最新数据比较旧草案参数与当前设置。没有参数快照的历史草案会明确提示无法复现旧参数。算法版本不同也会提示两组参数均用当前算法试算，不能当作旧算法的精确重放。确认后才取消旧草案并创建新请求；旧记录保留，人工选择不自动复制到新候选。最终分析会重新读取数据，因此预览不是对未来结果的保证。

## 实现边界与验证

- `shared/initialization-matching.ts`：配置、默认值、预设和试算协议。
- `server/lib/config/initialization-matching-validation.ts`：范围、枚举、别名冲突、配置兼容。
- `server/lib/source-initialization/matching-normalization.ts`：标题、艺人和版本证据。
- `enhanced-matching.ts`：候选核验、分级、排序和冲突保护。
- `matching-preview.ts`：只读快照、统计与逐首比较。
- `matching-snapshot.ts` 与 `service.ts`：参数与数据指纹、正式草案集成。

自动验证使用一次性数据库、模拟远端与实际元数据快照回放。浏览器验证设置编辑、保存、试算、错误恢复、过时结果及移动端布局。音频指纹、文件内容等价性、真实接管写入和下载不由候选试算证明；本功能不自动修复 Plex 刮削标签。
