# 初始化匹配与快速接管

首次媒体接管只用于歌单。它在第一次普通同步前分析网易云歌曲与 Plex 音乐，优先复用已有文件，缺少的再安排下载。专辑不进入这个流程，直接使用[同步流程](sync-flow.md#歌单与专辑)中的专辑行为。

分析本身不下载音频，也不修改 Plex 歌单；应用安排后才写入歌曲关联，并排队一次来源同步完成下载和 Plex 更新。

## 何时进入首次接管

全局“首次同步前启用媒体接管”默认开启；每个歌单可以继承或单独覆盖。关闭时不启动接管分析，普通同步按“未验证媒体”的设置处理；默认自动下载并托管，也可以改为等待手动选择。

启用后，方案尚未分析或确认时，普通同步会先进入首次接管，不会直接按未接管方式处理。要绕过这一步，需要明确选择“跳过接管”。

接管启用时，新建歌单会创建待处理方案。分析完成后系统先生成默认安排，候选列表默认展开。选择“审批初始化”时，方案只进入待确认状态，离开页面不会自动完成同步；尚未提交时会提示，草案仍保存在数据库中，重新打开可继续。选择“直接开始！”时会自动应用默认安排，并接续一次来源同步。一次添加多个歌单时，各自的分析、直接开始后的应用和接续同步都按来源队列顺序执行；审批方案等待确认后才继续。

“跳过接管”不提交当前方案。下一次普通同步按未接管策略处理，可能下载较多文件。停用的收藏仍可执行已提交的安排和接续同步；本次处理不会改变后续自动同步开关。

“开始下载并同步”只表示歌曲安排已经提交。后续来源同步完成、目标歌曲都有结果后，页面才会显示“Plex 已同步 N / N 首”；安排应用成功不代表音频已经入库。

## 默认安排与自动安排

审批初始化的默认草案会保留已确认文件，按推荐规则安排其余歌曲。“直接开始！”则采用当前排序的第一个有文件路径的候选，找不到候选才安排下载；艺人、版本和媒体归属差异保留为提示。

候选分类不限制用户明确采用候选。所有分类的“采用第一个候选”统一放在列表上方的批量操作栏，对本页选择或跨页全选的歌曲生效；没有候选的选中歌曲保持原安排。

普通自动安排保留人工修改。提交暂缓歌曲时选择“采用首个候选并开始”，会重新安排这些歌曲：有候选就采用第一项，不再按艺人中英文、版本差异或共享媒体规则改为下载；没有可用文件路径才安排下载。批量操作会覆盖所选范围内的草案选择，不创建撤销副本。

草案仍有暂缓歌曲时，提交前会列出数量与原因，并允许采用首个候选、返回调整，或明确只同步其余歌曲。主动暂缓的歌曲不会下载或加入 Plex。

## 快速方案与撤销

“按分数线重新安排”先按 0–100 的整数分数线预览：评分达到分数线的可用候选采用 Plex，其余安排下载。快速预览绑定当前草案版本、匹配快照和媒体身份，有效期为 20 分钟；草案内容、匹配快照或媒体身份变化后需要重新生成。

这个操作会重写未提交的手动选择，已确认文件仍保留。共用一个文件的歌曲会一起处理，来源歌曲仍分别记录。

- “只保存，不执行”只改草案，并保存执行前的选择。草案未再次编辑时，可用“恢复之前的选择”撤销。
- “开始处理”会立即把这份安排提交到持久队列，同时释放撤销数据；处理完成前不能继续编辑。
- 取消尚未执行的提交会保留当前歌曲选择，但不会自动恢复快速方案前的安排。已经开始应用后，取消不会再回滚已经完成的本地关联或 Plex 操作。

重复提交同一个准备请求不会再次应用方案。已结束方案的全部歌曲安排和评分证据仍可查看。

## 取消与服务重启

取消分析会停止本轮网易云与 Plex 查询，不提交任何歌曲安排；只要接管仍启用且没有明确跳过，下一次普通同步仍会重新进入分析。已经排队的安排可以取消；尚未开始的请求会直接结束，正在应用的请求会收到取消信号，当前歌曲选择仍保留。重新提交时会再次核对来源歌单、绑定版本、文件归属和精确路径。

应用开始前的取消会阻止写入；应用已经开始后，取消不会倒回已经完成的媒体关联，也不会撤销后续同步已经写入 Plex 的结果。

服务重启时，尚未完成的首次分析或安排应用请求会重新进入来源队列并继续核对。分析已经完成并接续普通同步时，接续同步按普通来源请求恢复：尚未开始的请求继续排队，执行中的请求记为“任务被中断”并消耗一次失败额度，等下一次调度或手动重试。

## 评分与风险

评分满分 100，只比较元数据：标题 35 分、艺人集合 35 分、时长 20 分、专辑 7 分、曲序 3 分。有争议的版本差异每处扣 10 分，最多扣 30 分；缺失项不加分。文件名、音质和优先目录不是加分项；音质和目录偏好只在合格候选的评分及更靠前的排序项相同时参与稳定排序。

推荐规则和分数线方案会排除演唱者冲突、歌曲 ID 矛盾、版本冲突、媒体路径缺失或不唯一的候选。专辑或曲序按设置要求匹配时，缺失也会阻止推荐。明确选择“采用第一个候选”或“直接开始！”时，艺人、版本和归属差异仅作提示；执行仍核对所选文件是否存在、路径和绑定版本是否变化。

分数表示匹配程度，不是正确率，85 分也不保证匹配成功。分数线越低，误匹配风险越大，需要人工抽查；第一名和第二名接近时只提示风险。

## 设置分组

- “匹配总开关与预设”：增强匹配默认关闭。预设应用其覆盖的匹配参数，之后手动修改即成为自定义；切换预设保留艺人别名、标题别名、候选优先目录和快速初始化分数线。
- “标题与艺人规则”：控制简繁、全半角、双语、模糊标题、扩展召回，以及标题和艺人字段如何比较；路径只提供提示，不能单独建立关联。目标专辑唯一优选默认开启。
- “批量推荐策略”：多个候选时默认优选质量最高的合格候选，也可保留人工复核；忽略缺失合作歌手、拉丁重音、双语交叉、MusicBrainz 等增强项默认关闭，开启也不放宽版本和身份保护。
- “快速初始化”：只设置新分析草案中快速预览的默认分数线，默认 85；不改变已有方案，也不改变普通自动安排。
- “时长与版本规则”：区分直接推荐和人工确认；现场、伴奏、翻唱、混音等版本差异不会被时长或艺人证据掩盖。
- “别名规则”：管理艺人名称、标题别名和候选优先目录。目录偏好不影响下载位置。

## 艺人名与 MusicBrainz

“艺人名称”里的别名组让不同写法被当成同一艺人；“原名称 → 写入名称”是单独的写入替换，不会重命名已有文件。别名建议来自本次分析，需要确认保存才生效。

“艺人名称”页的“匹配别名”和“写入替换”都支持 JSON 批量编辑。匹配别名使用规则数组，每条包含 `name`（艺人名称）、`aliases`（别名数组）和 `enabled`（是否启用）；写入替换使用“原名称 → 写入名称”的 JSON 对象。应用只修改当前类型的规则，另一类保持不变；格式有误时保留输入。先应用到草稿，再使用页底保存条保存，取消批量编辑会保留原有规则。

MusicBrainz 是可选的外部补充，用来找艺人异名，默认关闭且要配合艺人别名使用。只发送待审艺人名，只采纳名称精确、没有同名歧义且达到配置最低搜索分的记录，不会自动修改手工别名。

## 重新分析、共享确认与纠错

修改当前匹配设置不会改写已有分析结果；新设置用于下一次分析。应用升级改变候选规则版本时，旧方案会标记为不兼容，只能查看，需重新分析后才能提交。Plex 音乐库在分析后发生变化时，页面只提示可以重新分析，当前选择和编辑权限保留。

“重新分析当前方案”会重新读取数据并生成新草案。已确认的媒体关联会保留，旧草案中未提交的选择需要重新确认。“重新分析匹配”只重评此前由系统自动选择、未经人工确认的关联；存在未完成的接管方案时，先取消或完成该方案。

待确认方案中，多首歌推荐到同一个 Plex 媒体时可查看整组信息并确认共用。共享保留每首来源歌曲的 ID 和关联，Plex 成员与排序规则见[同步流程](sync-flow.md#关联与未匹配)。按推荐规则生成的默认草案会优先尝试独立下载；明确采用首候选时允许共用。

已有绑定改为下载时，会进入托管副本纠错流程：新文件和 Plex 精确路径都验证后才切换，失败保留原文件与原关联。“暂缓”优先于旧关联停止本来源的处理，已有 Plex 条目仍受删除保护。新批准的下载不沿用旧失败历史；如果本轮再次失败并达到忽略条件，后续不会继续为它强制完整核对。

“歌曲与媒体”里可以做两种纠错：

- 更换匹配：改选其他 Plex 媒体，校验当前关联版本后保存；启用的收藏会自动对齐。
- 改为下载：另下一份托管副本，经 Plex 验证后才切换；失败保留原文件和原关联。

更换匹配验证新曲目后立即保存；“改为下载”在新文件可用前继续使用旧关联。启用的收藏会自动对齐，已停用的收藏需要手动同步一次。
