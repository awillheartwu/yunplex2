# reYunPlex 精简计划

> 建立时间：2026-08-21；最后核对：2026-08-23。S0–S6 已全部完成；本文保留为本轮减法的范围、顺序和验收记录，后续能力顺序以 `ROADMAP.md` 为准。

## 目标

把产品收敛成少量、职责单一的工作区，并减少需要同时维护的状态和入口。精简不以删除行数为目标，不能削弱 Source Convergence、媒体身份或 Plex occurrence 删除保护。

目标一级工作区：

1. **仪表盘**：只回答“系统是否正常、是否有问题、下一步做什么”。
2. **同步源**：管理 Playlist Source，并进入来源详情处理歌曲和媒体关联。
3. **手动下载**：解析、选择并提交一次下载。
4. **任务中心**：只展示正在执行的任务和可处理异常。
5. **设置**：保存真正影响运行行为的配置；低频危险项进入高级区。
6. **系统与运行**：监控、日志和历史运行的唯一入口。

最终不再保留独立的“媒体复用”一级入口，也不在多个页面重复展示下载历史、运行历史或异常队列。

## 排序规则

每个候选项按以下顺序判断，而不是按页面观感推进：

1. **事实源风险**：是否存在两套可写状态或互相同步的缓存。
2. **用户心智收益**：是否能减少一级入口、重复操作或不明确的归属。
3. **实施风险**：是否触碰身份、删除授权、下载 lease 或 Source Convergence。
4. **可验收性**：是否能在一个独立提交内完成迁移、测试和文档闭环。

同一时间只允许一个阶段处于“进行中”。没有达到验收门槛，不进入下一阶段。

## 执行顺序

### P0 — 先停止继续膨胀

#### S0. 已完成的基线剪裁

状态：**已完成并提交**。

- 删除动态页、活动事件后端和数据库内容。
- 把系统监控、日志和运行记录收敛到“系统与运行”。
- 退役 provider、MusicBrainz、弱元数据候选和审核队列，只保留托管精确路径与 Explicit Adoption。

保留：Source Convergence、`song_identity_bindings`、`local_media_assets`、逐 `playlistItemID` 删除授权。

#### S1. 下载、任务和历史入口收敛

状态：**已完成并通过代码门禁**。

保留：

- 手动下载的解析、选择、配置、提交和保存为同步源。
- 任务中心的实时进度、取消和异常处理。
- 系统与运行中的历史运行与详情。
- `download_tasks` 的队列、lease、幂等和重启恢复。
- `task_runs` 与 `failure_records`。

删除或迁移：

- 删除手动下载页的下载历史和完整队列管理。
- 删除任务中心中的最近历史和重复同步入口。
- 删除无调用的下载历史、批量重试、清空和删除 HTTP 入口。
- 历史链接统一迁移到 `/system?tab=runs`。

验收：

- 三个工作区不存在重复历史列表。
- 进行中的下载仍能在任务中心实时刷新。
- 单项失败仍可从运行详情或异常处理重试。
- 全量测试、lint、typecheck、build、仓库大小和 diff 检查通过。

#### S2. 数据生命周期与系统维护收敛

状态：**已完成并通过代码门禁与数据库副本验收**。

原因：当前 `data/data.db` 约 144 MB，其中 `task_runs` 约 120 MB；大量 partial run 把完整歌曲 JSON 保留 90 天。数据增长已经比页面样式更优先。

保留：

- 最近运行详情。
- 未解决的 `failure_records`。
- `local_media_assets` 和 Media Link，不随运行历史清理。
- 日志、运行、下载任务使用不同的合理保留周期。

精简：

- 删除确认无读写的 `sync_state` 投影和无调用的 `cleanupOldSyncRuns()`；0 字节 `data/app.db` 作为单独、可恢复的数据清理处理。
- 运行详情采用分层和容量双重保留：完整歌曲/步骤详情最多保留 7 天且全库合计不超过 8 MiB，超出任一上限即压缩为列摘要；partial/failed 摘要最多保留 14 天，成功/取消记录保持 7 天。
- 不新增长期 `run_song_tasks` 历史表；旧运行超过详细期后不再提供逐歌曲重试，未解决问题继续由 `failure_records` 承担。
- `failure_records` 的 open/ignored 状态持续保留；resolved 保留 30 天。`failure_occurrences` 保留 90 天且每个 fingerprint 最多 50 条。
- 清理 `task_runs` 时同步处理悬空的 `playlist_sources.last_job_id` 和异常关联，维护结果统计必须与实际变更一致。
- 把保留维护从“下一次同步顺便执行”改成启动时一次、之后每 6 小时一次的独立维护任务。
- 自动清理成为默认行为；系统页已移除大块“运行记录维护”操作和对应 HTTP 接口。
- 清理时只删除完成/失败的执行明细，不删除运行中的 lease、媒体来源事实和未解决异常。

验收：

- 使用数据库副本验证清理前后数量、大小和引用完整性。
- 新鲜 SQLite、旧库迁移、运行中任务保护、未解决异常保护均有测试。
- 连续运行不会让 `task_runs` 与 `failure_occurrences` 无界增长。
- 数据库副本执行压缩和 `VACUUM` 后，目标文件体积低于 40 MB；运行时不自动 `VACUUM` 正在使用的数据库。
- 真实测试数据库的清理作为独立、可恢复步骤执行，不与 schema 变更混在一起。

验收结果（2026-08-23）：数据库副本和真实测试库均通过 `integrity_check`。真实测试库从 137 MB 压缩到 27 MB；运行记录 1804 → 1038、已解决异常 153 → 55、异常出现记录 5177 → 1486、下载任务 307 → 269。166 条 Local Media Asset 和 168 条 Media Link 全部保留，运行引用无悬空。原库已先做独立备份，运行时自动维护不执行 `VACUUM`。

二次增长审计（2026-08-23）：27 MB 主库中 `task_runs` 占 22.53 MB；353 条近期定时 partial/failed 详情独占 19.33 MB，是数据库继续增长的明确主因。加入 7 天与 8 MiB 双重详情上限、14 天失败摘要上限及 6 小时维护周期后，旧库副本从 1038 条运行、20.04 MB JSON 收敛为 352 条、7.38 MB JSON；主库离线 `VACUUM` 后为 11.13 MB。媒体资产、身份绑定和运行引用完整性再次通过检查。

### P1 — 收敛状态与主流程

#### S3. 失败状态单一写入责任

状态：**已完成并通过代码门禁与真实测试库迁移验收**。

目标责任：

- `download_tasks`：执行状态与重试输入。
- `task_runs`：一次运行发生了什么。
- `failure_records`：当前是否需要用户处理。
- Playlist Source：只保存来源摘要，不再保存第二套歌曲失败清单。

精简：

- 盘点并迁移 `copyright_restricted_ids`、`ignored_failure_ids` 与 `failure_records` 的重叠。
- 让下载终态或 Source Convergence 中的一个明确提交点负责写入异常，其他路径只读取。
- 同步源失败计数和仪表盘待处理项统一从异常读模型派生。
- 删除依赖错误字符串判断的重试决策，后续再接 ROADMAP 的统一错误分类。

验收：

- 同一失败只产生一个稳定 fingerprint 和一个当前状态。
- 重试成功会关闭异常；版权受限和忽略策略不会被误重试。
- 删除一个重复字段前完成数据迁移和新旧库测试。
- 不改变媒体身份、下载 lease 或 Plex 删除授权。

验收结果（2026-08-23）：`failure_records` 已成为来源当前异常的唯一事实源；来源级运行只在 `saveSyncRun()` 投影一次异常，下载队列不再重复写入。旧库中的 `copyright_restricted_ids` 与 `ignored_failure_ids` 已迁移后删除，来源列表和仪表盘计数改为实时派生。真实测试库升级到 schema v49，38 条未关闭异常、166 条 Local Media Asset 和 168 条 Media Link 均保留，旧列与派生的 `ignored_failure` 当前记录为 0，`integrity_check` 为 `ok`；迁移前已生成独立备份。

#### S4. 来源中心化的歌曲与媒体管理

状态：**已完成并通过代码门禁**。

精简：

- 建立 Playlist Source 详情，以当前 occurrence、Media Link、Local Media Asset 和异常状态组合出歌曲列表。
- 将日常“使用已有媒体/取消接管”放入来源详情的歌曲上下文。
- 移除侧边栏“媒体复用”一级入口。
- 仅保留弱入口的全局高级关联视图，用于孤立绑定和跨来源影响；不复制第二套绑定。
- 明确提示一次 Explicit Adoption 会影响引用同一网易云歌曲的所有来源。

验收：

- 日常媒体处理可从同步源完成。
- 全局绑定仍以网易云歌曲 ID 为唯一事实，不变成来源级绑定。
- 孤立绑定仍可发现和取消。
- 托管精确路径、重复路径冲突和外部媒体保护测试保持通过。

验收结果（2026-08-23）：同步源展开项改为读取当前 occurrence、Media Link 与 Local Media Asset，不再依赖会被压缩的最近运行歌曲。Explicit Adoption、解绑及 Plex 路径验证都进入“媒体与歌曲”上下文，并明确提示网易云歌曲 ID 级别的全局影响。侧边栏已删除“媒体复用”；`/match-reviews` 仅保留孤立关联清理，已解绑 tombstone 不再出现。旧的最近运行歌曲接口和重复的“仅刷新目标清单”接口已删除，身份事实、下载保护和逐 occurrence 删除授权未改变。

### P2 — 最后做界面和外围清理

#### S5. 仪表盘、系统页和设置减负

状态：**已完成并通过代码门禁与浏览器验收**。

仪表盘只保留：系统状态、立即同步、来源健康、待处理事项和当前任务入口。优先删除不产生操作决策的最近 Plex 列表、重复 KPI 或大趋势卡，而不是先换皮肤。

系统页只保留：依赖健康与必要资源指标、日志、运行历史。自动保留已经可靠后，移除常驻维护面板；诊断复制和危险操作进入高级区。

设置页按“日常、媒体产物、高级安全”重新分组；不再暴露已经退役的匹配策略或可由系统自动决定的内部参数。

初始化向导和设置页的网易云、Plex、下载目录检查统一复用 `server/lib/config/connection-test.ts`，删除 setup 自己维护的第二套连接判断。同步触发保留“仪表盘全局同步”和“同步源单源/批量同步”；任务中心不再触发同步，自动同步策略以设置页为权威。

验收：每个首屏都能用一句话说明用途；相同动作只出现一个主入口；桌面和移动端完成关键旅程检查。

验收结果（2026-08-23）：仪表盘已删除趋势图、重复 KPI 和“最近添加到 Plex”，只保留依赖状态、同步动作、当前任务入口、待处理事项与来源健康。系统监控已删除资源折线图、数据库逐表统计和重复运行环境面板，只保留依赖健康及 CPU、RSS、运行时间、数据库大小；采样间隔从 3 秒降为 10 秒，常规采样不再逐表计数。设置从 5 个标签收敛为“日常、媒体产物、高级”，恢复默认与重新初始化进入危险操作。setup 与设置页通过同一个连接测试服务验证网易云、Plex、目录和路径发布。桌面与 390px 浏览器检查无横向溢出和控制台错误；构建转换模块 2686 → 2077。

## 精简期间的暂停项

以下能力在 S1–S4 完成前曾暂停。精简阶段关闭后，不再由本文阻塞；是否实施及顺序以 `ROADMAP.md` 为准：

- 来源级持久调度与新队列。
- 音质升级/替换策略。
- 情绪、subtype 等元信息扩展。
- 框架迁移、前后端拆分或 Tauri。
- 只调整配色、卡片和动画但不减少职责的 UI 重做。

## 每阶段交付纪律

1. 开始前记录 `git status --short`，不得覆盖其他阶段的未提交改动。
2. 先写清“保留、删除、迁移、不触碰”，再改代码。
3. 数据删除先备份并在副本验证；schema 迁移与真实测试数据清理分开提交。
4. 一个阶段一个可独立回退的提交；阶段之间不并行。
5. 至少执行相关测试、`npm run typecheck`、`npm run lint`、`npm run build`、`npm run check:repo-size` 和 `git diff --check`。
6. 涉及网易云、Plex、重启或长时间运行时，代码门禁与真实外部验收分开报告。
