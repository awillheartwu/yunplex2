# 同步流程

同步把网易云歌单对齐到 Plex：缺的音频下载下来，顺序不一致就调整，多出来的条目按规则处理。

## 模式与跳过

| 入口     | 做什么                                                   |
| -------- | -------------------------------------------------------- |
| 同步     | 两边都没变化就跳过；连续跳过多次或隔太久会做一次完整比较 |
| 完整比较 | 重新核对两边全部成员与顺序；网易云歌曲详情复用本地缓存   |
| 预览     | 只查看比较结果，不下载、不修改 Plex 或业务状态           |
| 重建关联 | 保留人工选择，重新评估自动关联后再完整比较               |
| 重新下载 | 只重下 YunPlex 管理的音频，新文件校验通过才替换          |

跳过前会顺手检查本地文件：缺文件、文件不对劲，或 Plex 歌单的成员、顺序、文件路径被别人改过，都会进入完整处理。专辑不做跳过。

已经确认不可重试或达到重试上限的失败不会让每轮都重跑；它们保留在任务中心，等手动重试、周期完整比较或问题本身变化后再处理。仍有待处理失败、待应用的媒体纠错或目标变化时，同步不会跳过。

## 关联与未匹配

YunPlex 只认两种关联：

- 托管关联：文件由 YunPlex 下载，Plex 里恰好有一条路径指向它。
- 明确接管：你在“歌曲与媒体”中选择，或明确按首次准备的自动方案采用这个 Plex 媒体。首次流程见[初始化匹配与快速接管](initialization-matching.md)。

Plex 里的标题、艺人、专辑、时长只是展示，改它们不影响关联。手动接管失效时系统不会猜；取消接管后，下次同步按未接管处理。

对不上的歌按设置处理：下载一份带歌曲 ID 的独立副本，或等你手动选。已存在的外部文件不会被覆盖，也不会被悄悄接管。

## 下载队列

默认音质在「偏好设置 → 下载与文件 → 音质偏好」设置。新建收藏或进入歌单、专辑的「设置 → 下载设置」可为这份收藏单独选择音质；默认继承全局设置，切回继承后使用之后的全局值。音质选择用于新提交的下载任务，已有文件不会因此自动重新下载，已排队任务与重试沿用任务保存的音质。

下载和补全共用一条队列，同时能下几首由全局设置决定，不按歌单叠加。

- 断线、超时、上游报错会自动重试有限次；服务重启后接着排没做完的。
- 网易云限流时整条队列停一会儿，过后自动继续。
- 登录失效、磁盘满或目录不可写会暂停队列；处理完在活动页点“继续下载队列”。
- 版权受限或文件不合法的歌不重试。
- 同一首歌被多个地方用到时只下一次；取消一方不影响其他调用方继续使用这份下载。

完整下载并校验过的音频暂存在数据目录的 `download-cache/`，按文件任务隔离，不进入 Plex 音乐库。写标签使用独立副本，失败或中断后重试复用原音频；音质沿用该任务保存的选择。只有标签与音频校验通过后才原子切换目标文件，已有文件在失败时保留。任务结果保存成功后清理缓存，自动维护按下载明细保留期清理过期缓存和已删除任务的残留，正在处理的任务不清理。

FLAC 通过 `flac-bindings` 调用 libFLAC 处理元数据，无需整首音频读入内存，支持无填充块并保留未管理的标签和其他元数据块。前置 ID3v2 在工作副本中分块移除，避免旧标签干扰读取。重复写入只替换正面封面；封面嵌入和文字标签开关独立生效。MP3 继续使用 `node-id3` 更新，保留未管理的标签。

标签写入和 `music-metadata` 回读核验在同一个 Worker 中执行，共享取消和超时边界。FLAC 核对全部受管理字段，MP3 核对主要歌曲字段；嵌入封面时检查正面封面的数量和内容。核验失败不发布工作副本。这是标签核验，不是完整音频解码；日常同步复用文件仍使用轻量文件头检查。

只要还有进展就一直等，长时间没动静才提示停滞。活动页可以暂停某次运行，当前文件下完为止。

## Plex 完成条件

Plex 更新需要先按精确路径识别音频。写入歌单后会重新读取成员和顺序，与本次同步计划核对；下载完成不代表歌单已更新。

Plex 请求使用官方 API 1.0 的 JSON 接口，单次请求超时为 30 秒；歌单写操作不自动重试。取消来源请求会中止其接口等待，共享文件任务使用独立的取消信号。

后台持续订阅 Plex 的活动和媒体变化事件，同一服务器与账号共用一个 SSE 连接；断线后自动重连，长时间收不到数据也会重建连接。修改连接设置和关闭应用时释放原连接。扫描在发起 POST 前注册监听，只使用本次请求发起后的活动，按响应的活动 ID 关联；未提供 ID 时，只使用有明确分区上下文的活动判断完成。结束事件提前唤醒核对并刷新路径索引，无法关联的结束事件只触发核对；订阅不可用时继续轮询。扫描完成或取消后释放本次监听，后台连接保留。

系统同时核对当前分区的扫描状态、扫描时间变化，并持续按本批文件的精确路径查找；第一次读取为空闲不能证明本次扫描已经完成。扫描活跃或完成状态尚未确认时延长等待窗口，默认扫描等待窗口为 10 分钟；配置的普通核对窗口更长时沿用该值。扫描完成后按重试次数和间隔留出索引稳定时间，扫描结束和最终核对时重新读取路径索引。全部目标文件已可验证时即可继续，不必等待无关的后台分析。

超出窗口时保留文件和未匹配状态，分别说明扫描仍在运行或目标路径仍不可见。后续同步复用已经有效的托管文件，不因首次接管中的下载决定再次下载；明确的替换操作仍按原规则执行。活动页单独显示 Plex 扫描进度；没有百分比时显示等待状态，不混入文件下载进度。

后台每分钟核对音乐库状态，优先用 `contentChangedAt` 区分内容变化和空扫描；没有该字段时参考扫描时间与已收到的媒体事件。事件和重连会提前触发核对。正常同步、首次接管或补全正在运行时，昂贵的索引和歌单检查延后，扫描状态仍可更新。

开启自动同步且收藏已启用时，后台会检查未忽略的 Plex 匹配失败。只有当前目标、有效且未被替换的托管文件和唯一的精确 Plex 路径都能确认，才排队补齐索引；人工接管、待确认的首次接管、其他阶段失败和忽略项不进入自动恢复。恢复经由原来源队列串行执行，不下载、不发起扫描、不删除条目，也不创建歌单。排队时保存网易云曲目、Plex 歌单和关联版本快照，执行前再核对；快照变化则延后到正常同步。写后仍核对成员和顺序，实际成功后才解决对应异常。

已连接的 Plex 歌单会在相关事件、重连后以及每五分钟核对一次内容指纹和每个条目的文件路径；成员、顺序或路径变化都会提示，外部编辑或删除只在收藏详情提示，不由事件直接覆盖。歌单成员与顺序的事件覆盖不作保证，定时核对保留。音乐库在首次接管分析后发生变化时，页面提示可以重新分析，保留当前草案选择。

网易云使用 `@neteasecloudmusicapienhanced/api`。普通歌单同步先读取歌单摘要和有序成员，再只为本地没有详情的歌曲调用 `song_detail`；详情原文保存在 `netease_song_details`，后续同步按当前艺人别名重新映射。没有拿到发布日期的详情不会长期缓存，下次同步会重新尝试。首次接管和审核流程仍按需读取完整详情。获取音源的 `song_url_v1` 首次调用时，共享一次有 30 秒时限的 XEAPI 密钥初始化，沿用 SDK 的密钥获取与签名校验，缓存位于 SDK 使用的系统临时目录；失败后可以重试。登录、歌单、专辑、歌词和收藏接口不等待该初始化。无需用户申请额外密钥或手动注册，原 Cookie 仍用于登录及音源权限。调用者取消或连接检查超时会停止自身等待，不影响其他调用者共享的初始化。

网易云接口的失败信息包含接口名称、耗时与状态，超时和取消也覆盖歌单解析、收藏读取及连接检查。SDK 错误及初始化日志统一脱敏。未返回音源不直接等同于版权受限；试听音源与不支持的音频格式不能作为完整歌曲保存。补充发布日期的旧详情接口只提供可选信息，失败不会使完整的主接口结果失效。

移除多余条目前，需要目标完整、关联没变，并按设置中的删除策略确认它确实多余；写完还会重新读取结果。同步只移除歌单条目，音乐文件保留。
