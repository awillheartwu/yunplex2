# 同步流程

同步把网易云歌单或专辑对齐到 Plex：下载缺失音频，调整顺序，再按设置处理多余条目。

## 歌单与专辑

- 歌单的来源级自动同步默认开启，但全局“启用自动同步”默认关闭；定时运行需要两者同时开启。歌单还受“首次同步前启用媒体接管”控制，首次准备见[初始化匹配与快速接管](initialization-matching.md)。
- 新建专辑默认关闭自动同步，也不会进入首次媒体接管。手动输入专辑 ID 时会补取名称、封面和曲目数；无法取得专辑名称时返回错误，不保存占位收藏。单来源的“同步”仍可手动执行；需要定时更新时，在收藏设置中启用自动同步。
- 专辑每次都读取整张专辑并做完整比较，不按网易云更新时间跳过。歌单的同步数量上限只截取歌单，默认处理前 10 首，设为 0 表示不限；专辑不使用该上限，设置页也不显示此项。
- “添加后自动下载”和“仅下载不入歌单”默认关闭。前者开启时，添加专辑会立即请求一次完整同步，但不会打开后续自动同步；后者开启后，不创建或更新 Plex 歌单。

音乐库的多选“同步”只用于已启用歌单；专辑和已停用歌单从来源详情执行单来源请求。

来源设置里带“继承”的状态覆盖使用继承、开启和关闭三种独立状态；选择继承才使用全局值，明确关闭不会被当成未设置。

## 模式与跳过

| 入口                       | 做什么                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------- |
| 同步                       | 执行普通同步；无变化的歌单可以跳过，专辑始终完整比较                                                     |
| 检查同步                   | 重新核对全部成员与顺序，不依赖本轮变化判断                                                               |
| 重建托管关联               | 保留人工选择，重新建立托管文件关联后完整比较；不重新按标题、艺人评分                                     |
| 重新下载                   | 仅歌单可用；默认重下托管音频并补齐缺文件，勾选“也替换原来就有的文件”后也可替换外部文件，人工绑定始终保护 |
| 预演（`preview` 诊断模式） | 只生成比较结果，不下载，也不修改 Plex 或来源业务状态                                                     |

“重新下载”会为新文件完成音频校验和标签处理后，才替换旧文件；失败时继续使用旧文件。

`preview` 通过 API 或诊断入口使用。诊断脚本的预览仍会初始化数据库、读取配置并访问外部服务，使用要求见[诊断](operations.md#诊断)。

普通歌单同步会先比较网易云快照和已知异常。跳过前还会检查本地文件与 Plex 歌单：缺文件或文件不可用会转入完整处理；“自动修复 Plex 歌单改动”默认开启时，歌单成员、顺序或媒体路径被外部修改也会转入完整处理。连续跳过上限默认 5 次、完整比较间隔默认 7 天，任一条件达到时也会完整比较；设为 0 可关闭对应条件。

只有不复用快照绑定、重新核对全部目标的轮次才更新完整比较时间；复用旧绑定的增量同步和纯换序不会延后按天触发的完整比较。

## 调度与请求

来源分析、安排应用和普通同步都保存到持久队列，并按来源逐项执行；同一时刻只运行一个来源请求。一次提交多个来源时，后续请求等待前一个结束。自动调度只处理已启用且全局自动同步已开启的来源；同步间隔未单独设置时继承全局值，默认 30 分钟。单来源手动请求可以执行已停用的来源。停用来源或关闭全局自动同步会取消尚未执行的定时请求，已经接受的单来源手动请求仍可运行。

跳过轮次保留真实目标数量和已知异常数量；列表摘要显示无需变更和结果计数，跳过原因与上次未解决结果放在运行详情中。详情标明本轮没有重新执行逐首核对，不重复保存整张歌单的歌曲明细。

获取来源或核对媒体期间失败时，运行摘要显示错误原因，详情保留失败步骤与诊断。尚未生成歌曲明细的失败轮次显示“本轮未完成核对”，不能解释为来源为空或无需变更。

## 失败与重试

同步失败统一使用「偏好设置 → 同步策略 → 失败次数上限」，默认 3 次。上限包含首次失败：本轮失败立即保存记录，下一次来源同步再尝试，达到上限后自动进入“已忽略”。网络、下载、标签、Plex 匹配及歌单写入、详情暂缺、音频校验和未知错误遵守这套次数。版权受限、认证失效、音源不可用、格式不支持、媒体身份冲突和请求无效不自动重试，修复外部条件或完成明确选择后可手动重试。

已忽略的单曲不再补取详情、下载或重新匹配；普通同步、周期完整比较、重建托管关联和重新下载都不会自动启用它们，其他歌曲和新增歌曲继续处理。具体歌曲的 Plex 写入失败只记录到该歌曲，运行详情保留整轮诊断，不另生成一条阻挡整个来源的错误；部分歌曲成功时，来源显示部分失败。

来源连接等整轮错误同样保存异常记录，达到上限后定时同步跳过该来源。明确点击“同步”会重新开放该来源自身的忽略错误，重新分配失败次数额度并读取最新歌单；已忽略的单曲保持不变。首次接管尚未完成或请求未接受时，不改变错误状态。仍有待处理失败、待应用的媒体纠错或目标变化时，同步不会按无变化跳过。

手动重试按歌曲的当前归属分流：歌曲仍是来源当前成员时，提交一次 `retry` 来源同步，并完整比较该来源；只缺音频时才下载，Plex 匹配或歌单写入失败复用已有媒体。替换、标签和补全任务失败后会重新执行原文件任务，保留目标文件、操作选项、音质和音频缓存；本轮等这些任务结束后再更新 Plex。只复用有效音频不能解决尚未完成的文件操作，补写标签也不能解决替换失败；原任务或等价的替换操作实际完成后，替换异常才可解决。重试不重新打开原来的历史运行。只有所选的忽略项会重新开放，其他忽略项保持忽略，相关来源连接错误也一起重新开放。还没有形成来源成员记录、但异常关联着失败文件任务的歌曲，会直接重新入下载队列；已有历史成员记录但不是当前成员时不会走文件任务重试。首次媒体接管尚未完成或存在身份冲突时，需要先完成明确选择。

移除多余条目失败时，按具体 Plex 歌单和 `playlistItemID` 保存异常，使用同一失败次数上限。达到上限只忽略该条目的移除，其他歌曲继续同步；在异常处理或运行明细中手动重试，只重新开放选中的条目。移除成功，或重新读取歌单确认该条目已不存在后，异常转为已解决。

异常记录显示待处理、已忽略、已解决三种状态，以及失败次数、当前上限、自动或手动忽略、累计失败和手动重试次数。明细用红色表示待处理、黄色表示已忽略、绿色表示已解决；运行详情把当前处理状态与本次运行结果分别展示，后续重试成功不会改写历史失败。手动重试为所选项重新分配完整的失败次数额度，同时保留累计历史。收藏页的来源批量重试只选择待处理异常；已忽略项可在异常处理中单独重试。异常处理的批量重试只处理未解决项，批量忽略只处理待处理项；所选项已全部忽略或解决时，页面直接说明无法再次忽略的原因。重试按钮是否存在取决于问题是否仍关联到当前歌曲或文件任务；错误原因只用于诊断和自动恢复策略。从运行详情进入异常处理时，默认查看本次运行关联问题的全部当前状态，问题后来忽略或解决后仍可查到。

## 关联与未匹配

YunPlex 只认两种关联：

- 托管关联：文件由 YunPlex 下载，Plex 里恰好有一条路径指向它。
- 明确接管：你在“歌曲与媒体”中选择，或明确按首次准备的自动方案采用这个 Plex 媒体。首次流程见[初始化匹配与快速接管](initialization-matching.md)。

人工接管优先；普通同步不会用自动匹配覆盖它。

关联按网易云歌曲 ID 共用，不按收藏分开。同一首歌出现在多个收藏时，更换或停用关联会影响所有使用它的来源。

多首来源歌曲明确关联同一个 Plex 媒体时，各自的关联与同步结果分别保留，Plex 歌单只保留该媒体首次出现的一项。完整同步、纯换序、写后校验和“验证 Plex”都使用这个成员规则，完整性按来源歌曲是否都有强关联判断。移除其中一首不会移除另一首仍需要的媒体；全部移除后按原有多余条目策略处理。共用媒体是正常同步结果，不进入异常处理，详情显示来源歌曲数与实际 Plex 媒体数。

Plex 里的标题、艺人、专辑、时长只是展示，改它们不影响关联。手动接管暂时失效后，仍可按原来的精确路径恢复；找不到唯一的原文件时不会猜。在“歌曲与媒体”中点“停用”后，下次同步会重新选择或下载；原文件保留。

对不上的歌按设置处理：下载独立副本，或等你手动选。下载路径严格按命名模板生成，只有模板明确包含 `{songId}` 才写入歌曲 ID，不额外追加 ID 或 YunPlex 后缀。艺人、专辑和歌名里的 `/` 会替换为全角 `／`，不会变成额外目录；模板与受保护文件实际冲突时明确报错，由用户选择复用或调整模板。普通同步不会覆盖或悄悄接管已存在的外部文件；首次接管和“重新下载”中的明确替换是例外。

## 下载队列

默认音质在「偏好设置 → 下载与文件 → 音质偏好」设置。新建收藏或进入歌单、专辑的「设置 → 下载设置」可为这份收藏单独选择音质；默认继承全局设置，切回继承后使用之后的全局值。音质选择用于新提交的下载任务，已有文件不会因此自动重新下载，已排队任务与重试沿用任务保存的音质。

获取音源从所选档位依次向下尝试：母带、环绕、Hi-Res、无损、320k、192k、128k，拿到完整的 FLAC 或 MP3 地址即停止。空地址、试听与不支持的格式继续尝试低一档；全部不可用才记录最终错误，整条音质尝试只算本轮的一次处理。网络、限流或登录错误直接沿用统一错误机制，不继续切换音质。

临时下载直接创建独立下载批次，不进入首次接管，也不会自行更新 Plex 歌单；只有后续来源同步会按关联结果更新播放列表。

下载和补全共用一条队列；默认同时处理 3 首，实际并发由“下载并发数”决定，不按歌单叠加。

手动下载关闭“下载封面”后，本次任务也不会保存独立封面或艺人图片；这份选择保存在文件任务中，后续排队和重试不会被全局图片开关覆盖。

“补全标签和词图”只处理已有音乐文件，补写标签及按设置补全歌词和独立图片，不调整 Plex 歌单。找不到音频的歌曲会跳过；歌单读取失败直接报错，文件任务中的歌曲信息读取失败按统一错误机制记录，不当作跳过。

- 每个文件任务执行一次，失败后不会自行循环；它属于当前来源歌曲时由下一次来源同步按统一失败次数处理，否则从异常记录手动重试。下载队列没有独立的延迟重试次数。
- 网易云限流时整条队列停一会儿，过后自动继续。
- 登录失效、磁盘满或目录不可写会暂停队列；处理完在活动页点“继续下载队列”。
- 版权、音源或格式限制首次即忽略；音频校验失败按统一上限处理。
- 同一首歌的操作、音质、下载目录、目标路径及歌词、标签、图片选项全部一致时才共用活动任务；选项不同会形成独立任务，按提交顺序串行处理同一首歌。暂停或取消一方不影响其他调用方继续使用所需的文件。
- 文件写入同时按实际目标路径串行处理。下载目录可使用相对路径，运行时统一为绝对路径进行文件查找、资产保存、纠错暂存和冲突检查；现存相对路径记录仍能识别。同名歌曲命中同一路径时，后来的任务会报路径归属冲突，不覆盖或补写另一首歌的文件，也不自动改名。

完整下载并校验过的音频暂存在数据目录的 `download-cache/`，按文件任务隔离，不进入 Plex 音乐库。写标签使用独立副本，失败或中断后重试复用原音频；音质沿用该任务保存的选择。只有标签与音频校验通过后才原子切换目标文件，已有文件在失败时保留。最终替换前重新检查媒体纠错 ID 和关联版本，检查、替换及媒体记录提交在同一身份锁内完成；过期纠错任务不会先改文件再报冲突。任务结果保存成功后清理缓存，自动维护按下载明细保留期清理过期缓存和已删除任务的残留，正在处理的任务不清理。

“取消本批同步”会中止对应的网易云、Plex 接口等待，并取消同一批次中尚未开始的来源请求。本次运行独占的下载和标签任务也会中止，尚未开始的文件不再领取；同一文件仍被其他未取消、未暂停的运行使用时继续处理。用户取消不计为下载失败，也不消耗失败次数。删除收藏会先停用来源、取消其请求和独占文件任务，再清除来源信息；其他来源共用的任务及其记录保留。取消不会回滚已经写入的文件、绑定或 Plex 歌单。暂停下载队列只停止领取新文件，当前文件继续处理。活动页也可以只暂停某次运行：该运行尚未开始的歌曲不再领取，当前文件完成，其他运行继续；同一个文件仍被其他未暂停运行调用时，队列可以继续处理它。

服务重启或执行租约过期时，执行中的来源同步、下载和标签任务记录为“任务被中断”，消耗一次失败额度，不直接改回待执行；尚在排队的请求继续等待。执行中的来源同步等下一次调度或手动重试，独立文件任务等手动重试，已忽略项保持忽略。尚未开始的文件任务继续排队，音频缓存保留。首次准备的分析和应用请求会恢复并重新核对；应用后接续的普通来源同步仍按上面的来源请求规则恢复。

FLAC 通过 `flac-bindings` 调用 libFLAC 处理元数据，无需整首音频读入内存，支持无填充块并保留未管理的标签和其他元数据块。前置 ID3v2 在工作副本中分块移除，避免旧标签干扰读取。重复写入只替换正面封面；封面嵌入和文字标签开关独立生效。MP3 继续使用 `node-id3` 更新，保留未管理的标签。

标签写入和 `music-metadata` 回读核验在同一个 Worker 中执行，共享取消和超时边界。FLAC 核对全部受管理字段，MP3 核对主要歌曲字段；嵌入封面时检查正面封面的数量和内容。核验失败不发布工作副本。这是标签核验，不是完整音频解码；日常同步复用文件仍使用轻量文件头检查。

只要还有进展就一直等，长时间没动静才提示停滞。

## Plex 完成条件

Plex 更新需要先按精确路径识别音频。写入歌单后会重新读取成员和顺序，与本次同步计划核对；下载完成不代表歌单已更新。

Plex 请求使用官方 API 1.0 的 JSON 接口，单次请求超时为 30 秒；读写请求失败都直接交回本轮处理，不在接口层另设重试次数。同步失败按统一额度等下一轮处理。取消来源请求会中止其接口等待，共享文件任务使用独立的取消信号。

后台持续订阅 Plex 的活动和媒体变化事件，同一服务器与账号共用一个 SSE 连接；断线后自动重连，长时间收不到数据也会重建连接。修改连接设置和关闭应用时释放原连接。扫描在发起 POST 前注册监听，只使用本次请求发起后的活动，按响应的活动 ID 关联；未提供 ID 时，只使用有明确分区上下文的活动判断完成。结束事件提前唤醒核对并刷新路径索引，无法关联的结束事件只触发核对；订阅不可用时继续轮询。扫描完成或取消后释放本次监听，后台连接保留。

系统同时核对当前分区的扫描状态、扫描时间变化，并持续按本批文件的精确路径查找；第一次读取为空闲不能证明本次扫描已经完成。扫描活跃或完成状态尚未确认时延长等待窗口，默认扫描等待窗口为 10 分钟；配置的普通核对窗口更长时沿用该值。扫描完成后按“Plex 索引核对次数”和间隔留出索引稳定时间，默认核对 5 次、每次间隔 15 秒；这是一次同步内的路径读取，不重新下载，也不消耗多次失败额度。扫描结束和最终核对时重新读取路径索引。全部目标文件已可验证时即可继续，不必等待无关的后台分析。

超出窗口时保留文件和未匹配状态，分别说明扫描仍在运行或目标路径仍不可见。后续同步复用已经有效的托管文件，不因首次接管中的下载决定再次下载；明确的替换操作仍按原规则执行。活动页单独显示 Plex 扫描进度；没有百分比时显示等待状态，不混入文件下载进度。

后台每分钟核对音乐库状态，优先用 `contentChangedAt` 区分内容变化和空扫描；没有该字段时参考扫描时间与已收到的媒体事件。事件和重连会提前触发核对。正常同步、首次接管或补全正在运行时，昂贵的索引和歌单检查延后，扫描状态仍可更新。

后台事件只更新扫描状态、缓存和变化提示，不另外排队重试 Plex 匹配失败。尚有次数的失败等下一次来源同步；已忽略项等用户从异常记录手动重试。迟到入库的托管文件会在获准重试时按精确路径复用，写后仍核对成员和顺序，实际成功后才解决异常。

已连接的 Plex 歌单会在相关事件、重连后以及每五分钟核对一次内容指纹和每个媒体的全部文件路径；成员、顺序或任一文件路径变化都会提示，文件路径的返回顺序不影响判断。外部编辑或删除只在收藏详情提示，不由事件直接覆盖。歌单成员与顺序的事件覆盖不作保证，定时核对保留。

网易云使用 `@neteasecloudmusicapienhanced/api`。普通歌单同步先读取歌单摘要和有序成员，再只为本地没有详情的歌曲调用 `song_detail`；详情原文保存在 `netease_song_details`，后续同步按当前艺人别名重新映射。没有拿到发布日期的详情不会长期缓存，下次同步会重新尝试。首次接管和审核流程仍按需读取完整详情。获取音源的 `song_url_v1` 首次调用时，共享一次有 30 秒时限的 XEAPI 密钥初始化，沿用 SDK 的密钥获取与签名校验，缓存位于 SDK 使用的系统临时目录；失败后可以重试。登录、歌单、专辑、歌词和收藏接口不等待该初始化。无需用户申请额外密钥或手动注册，原 Cookie 仍用于登录及音源权限。调用者取消或连接检查超时会停止自身等待，不影响其他调用者共享的初始化。

网易云接口的失败信息包含接口名称、耗时与状态，超时和取消也覆盖歌单解析、收藏读取及连接检查。SDK 错误及初始化日志统一脱敏。未返回音源不直接等同于版权受限；试听音源与不支持的音频格式不能作为完整歌曲保存。补充发布日期的旧详情接口只提供可选信息，失败不会使完整的主接口结果失效。缺少详情的曲目仍保留原歌单位置；后续曲目和重复歌曲不会因过滤详情而错位保存结果。

移除多余条目前，需要目标完整、关联没变，并按设置中的删除策略确认它确实多余；写完还会重新读取结果。同步只移除歌单条目，音乐文件保留。
