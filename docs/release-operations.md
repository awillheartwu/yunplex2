# 首版安装、维护与验收

> 2026-09-29：Docker 与容器维护工作已暂缓，本文件中的部署步骤和维护工具作为后续实现草稿保留，尚不作为正式安装/备份保证。本体续接状态以 [路线图](../ROADMAP.md) 为准。

## 恢复部署工作前必须处理

- WAL 数据库检查可能修改备份包内的 `data.db-shm`，使刚报告成功的备份随后校验失败。应在临时副本上检查或规范化数据库后再生成清单，并加入带 WAL/SHM 的回归；不得把历史干净停机演练当作此边界已通过。
- 停机检查目前只能发现 Docker 容器，不能排除宿主机进程写同一目录；完善排他检查，并明确不支持维护与应用并行运行。
- 两次目录重命名之间存在断电窗口；补充可识别的恢复中断状态与启动保护，再复验恢复失败、断电和回退。
- 收紧输出目录校验时机、恢复阶段清单复用和可用空间提示；在正式使用前复验权限、路径隔离及业务数据一致性。
- 曾完成合成数据的旧版启动、备份、新版就绪、HTTP 登录、恢复与旧版回滚，但不代表上述边界和后续变更已验收。


## 支持边界

单管理员、自托管、单个 Nuxt/Nitro 进程与 SQLite。使用固定源码版本执行 Compose 构建，不提供自动生产部署或多实例共享数据库。Docker 按构建主机选择架构；只有验收报告列出的平台属于已验证范围。

增强初始化匹配是默认关闭的实验功能；已有用户配置保持不变。标准首次接管正式保留。预览和匹配建议不等于已绑定，仍须人工确认。

## 局域网安装

检出固定版本源码，编辑 Compose 的媒体挂载，使 `/mnt/nas` 对应真实音乐目录。数据目录使用专用宿主机目录，避免与音乐或其他应用数据混用。

```sh
docker compose build
docker compose up -d
curl --fail http://127.0.0.1:3000/api/system/ready
```

浏览器访问 `http://NAS地址:3000`，设置管理员密码并逐项检查连接。HTTP 会话不设置 Secure，HTTPS 会话设置 Secure；两者保留 HttpOnly、SameSite、同源与 CSRF 校验。HTTP 仅适用于可信局域网，不应直接暴露公网。

`/api/system/health` 检查进程存活；`/api/system/ready` 检查应用数据库和消费者，未就绪返回 503。首次安装的 `setup_required` 是可正常打开向导的就绪状态。外部服务离线不等于应用进程死亡。

容器对数据和媒体挂载必须具有所需读写权限；不使用 `chmod 777` 绕过权限。Compose 给正常退出预留两分钟；超时强制退出后仍须验证持久任务恢复。

## HTTPS 反代

反代必须保留用户访问的 Host（包含非默认端口），覆盖 `X-Forwarded-Proto`，正确追加客户端链。只配置实际代理的 IP 或最小 CIDR：

```sh
YUNPLEX2_TRUSTED_PROXIES=172.30.0.2/32 docker compose up -d
```

不要把示例地址照搬为真实配置；地址必须是应用实际看到的代理来源。默认不信任任何转发头，不支持 `*`。不要为了省事信任全部网络。来自不可信客户端的转发头不会影响 Cookie 协议或登录限流地址。

Nginx 的 location 示例（TLS 证书在反代侧配置）：

```nginx
location / {
    proxy_pass http://yunplex2:3000;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_buffering off;
    proxy_read_timeout 90s;
}
```

代理与应用同宿主机时可用 `YUNPLEX2_BIND_ADDRESS=127.0.0.1` 限制直接访问；代理在其他容器时按实际网络设置防火墙与地址。验收应从另一台设备完成登录、刷新、退出及重置密码，不能用 localhost 特例替代 NAS HTTP 验证。

## 停机备份与恢复

在 Compose 项目目录执行；工具要求已有且已停止的 `yunplex2` 容器，使用其镜像，不启动应用或调度器。首版工具支持 `/app/data` 的 **bind mount**，不支持命名卷。维护期间禁止启动任何使用该目录的应用，包括宿主机开发进程。

```sh
docker compose stop yunplex2
sh scripts/maintenance.sh backup /专用备份目录
sh scripts/maintenance.sh verify /专用备份目录/reyunplex-时间戳
```

备份包为目录，包含 `manifest.json` 和 `data/`，以便逐文件流式校验，避免大数据库被整体载入内存。记录应用版本、数据库版本、文件清单、大小和 SHA-256；凭据随应用数据保存，备份文件权限为 0600、目录为 0700。音乐文件不包含在内，由用户自行备份。不要把备份放进应用数据目录或版本库。

```sh
sh scripts/maintenance.sh restore /专用备份目录/reyunplex-时间戳
```

恢复先校验包与 SQLite，再复制到同一文件系统的临时目录并重新校验，最后替换数据目录。旧目录保留为 `data.before-restore-时间戳`。普通失败会回退；断电发生在两次目录重命名之间时，保持停机，检查并将保留目录恢复为原数据目录后再启动。工具需要对数据父目录的写权限，因此该父目录也应专用于本应用。

**备份目录有敏感信息。** 不上传工单、不公开分享；自行加密异地保存。验证成功只说明备份可读且一致，不等于业务恢复验收完成。

## 升级与回滚

1. 记录当前源码版本与容器镜像 ID，停机并备份；保留旧源码和旧镜像。
2. 切换到明确版本，构建并启动，不自动使用变化的分支头代替版本。
3. 检查 ready、登录、来源数量、配置、身份绑定和任务状态，再恢复正常使用。
4. 回滚时先停止新版本，用新版本维护工具恢复升级前备份，再切回旧源码/镜像启动。旧程序不得直接打开新版本已升级的数据。
5. 回滚不是撤销外部操作。升级观察期间如果改动了 Plex 或音乐文件，数据库恢复不会自动撤销这些操作；演练只使用专用测试数据与歌单。

## 发布硬门槛

- 完整本地质量门禁、生产构建浏览器旅程、首次 HTTP 安装和 HTTPS 可信反代验证。
- Forgejo Actions 的实际运行与分支保护证据；工作流文件存在不算平台验收通过。
- 隔离应用数据库、专用媒体目录与测试歌单的真实网易云/Plex验收；测试前后核对正式数据不变。
- 一次旧版本升级、失败回滚和业务数据对比演练。
- 同一候选版本连续 24 小时：前 12 小时空闲与连接切换，后 12 小时重复同步与受控失败恢复。重启测试单独进行，不累加中断前后的时长。
- 使用鉴权的 `/api/system/runtime` 采集内存、活跃资源、SSE 数量、队列、调度器、数据库体积及日志/运行数量；此接口不探测外部服务，也不输出凭据或路径。
